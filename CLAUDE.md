# S-mobiili · Säästä demo

A clickable React Native and Expo demo of a "clean up future spending before payday" feature for S-Bank's S-mobiili app. It was built for Junction and runs in Expo Go on Android and iOS. The UI copy is in **Finnish and English**; the presenter switches language on the Minä/Me tab.

The source design is `../S-mobiili – Raivaa tilaa -konseptit.html`. It's a bundled file of seven 390×844 mockups, so the HTML is packed and has to be unpacked before you can read it. Match its colors, type sizes and spacing; the tokens live in `src/theme.ts`.

## Commands

Run everything from this folder (`s-mobiili-demo/`), not from the parent `SPankki/`.

```bash
npx expo start            # dev server; scan QR with Expo Go (--tunnel if not on same Wi-Fi)
npx expo start --web      # browser
npx tsc --noEmit          # typecheck (must pass)
npx expo-doctor           # dependency/config check
npx expo install <pkg>    # add deps (never plain npm install <pkg>)
npm run deploy:web        # export web + eas deploy --prod --environment production → https://s-mobiili-demo.expo.app
npx expo export --platform web && npx expo serve   # run the production build (pages + /api/chat) locally
```

- **Expo SDK:** SDK 58, RN 0.88, React 19.3. APIs change between SDKs, so check `https://docs.expo.dev/versions/v58.0.0/` rather than relying on memory.
- **Native modules:** only use ones that ship in Expo Go. A dev build is out of scope.

## Architecture

- `src/i18n/`: the language layer. `lang.ts` holds the active `Lang` (`'fi' | 'en'`) outside React so `eur()` / `eur0()` in `theme.ts` format per language (`24,90 €` vs `€24.90`). `strings.ts` has the UI copy: `fi` is the source and `en: Strings` must match it key for key (functions for anything with numbers or plurals). `index.tsx` has `LangProvider`, `useLang()` (`lang`, `setLang`, `t`) and `useT()`. On web the choice is kept in `localStorage`; on native it starts in Finnish. Never hard-code UI text in a screen: add a key to both dictionaries.
- `App.tsx`: loads the Figtree fonts and sets up the providers (`LangProvider` outside `SaveProvider`). `Shell` calls `useLang()` so every screen re-renders on a switch. It renders only the current route with a slide-in transition, plus `TabBar`.
- `src/nav.tsx`: a small in-memory stack navigator with 5 tabs (`home | card | save | account | me`).
  - It provides `push / replace / back / goTab / resetTo` and handles the Android hardware back button.
  - **In-app navigation does not use Expo Router**, even though `AGENTS.md` says to. This was a deliberate call for a single-flow demo with shared state. Expo Router is installed only as a thin host: `src/app/index.tsx` renders `App`, `_layout.tsx` is a bare `<Slot />`, `+html.tsx` is the web page, and `api/chat+api.ts` is the chat's server route. Don't add screens there.
  - Only the top screen is mounted, so screens remount on return. The cleanup animation relies on that.
  - `back` sets `returnedFrom` (the closed route's name) on the entry it returns to, and `scrollY` / `setScrollY` keep a scroll offset per entry key. `Save` uses both: the outcome-bar intro and the transfer card's fade-in play only when the tab is opened (a fresh entry) or right after `review`; returning from anything else keeps the scroll position and shows the current state without animating.
- `src/state.tsx` (`useSave`): all app state.
  - Each suggestion has a decision: `pending | accepted | kept`.
  - `qty` holds the chosen quantity for reduce-type suggestions.
  - `cleaned` marks plan rows whose cleanup animation already ran.
  - `basketReady` tracks the prepared shopping basket.
  - `expensesOpen` is whether the "Arvioidut menot" dropdown on the Säästä tab is open (closed by default). It lives here so it survives the tab remounting.
  - `transferred` / `transferDeclined` hold the "Siirrä säästöön" decision. `transferOffer` (computed by `transferOfferFor`) is the suggested amount, or 0. It is deliberately *less* than what was saved this period (`TRANSFER_SHARE` 75 %, rounded down to `TRANSFER_ROUND` 5 €), so the transfer feels safe. It only shows once no suggestions are pending, and never leaves less than `TRANSFER_BUFFER` (50 €) on S-Tili on payday. With the defaults of the `basic` set that's 40 € of the 58 € saved, leaving ~82 € (~53 € even if half the savings fail). `transferOpen` is whether the transfer card is open (closed by default, like `expensesOpen`, and kept here for the same reason). `transferPick` is the amount chosen with "Siirrä eri määrä" (5 € steps, `transferRange`: 10 € up to whatever still leaves the buffer). `transferContext` gives the numbers to the card and the explainer.
  - `planForGoal(demo, goal, ids)` is the outcome-first "AI": fewest changes first, then the smallest overshoot, by brute force over subsets. It is currently unused: the +20 / +35 / +50 € goal chips were removed from the Säästä tab. `Review` and `OutcomeBars` still accept a `goal` prop.
- `src/data.ts`: all demo data, as **demo sets** built per language with `demoSets(lang)` / `demoById(id, lang)`. Each set and shared suggestion is a builder taking `L(fi, en)`, so both languages share the same numbers; ids are identical, so decisions survive a language switch. `Demo.lang` tells the explainer which texts to use. Dates are written `28.11.` in Finnish and `28 Nov` in English. The presenter picks one on the Minä tab ("Demosarja"); switching resets all decisions. Screens never import a set: they read `useSave().demo` (a `Demo` = the `DemoSet` plus `baseline`, `maxSaving`, `byId`, `find`, `planItem`). The choice isn't persisted, so a reload starts on the default set.
  - Each set has `today`, `payday`, `balance`, `savingsAccount`, `plan` (the spending forecast), `suggestions` (in review order), `transactions` and `shoppingBase`. `baseline` = balance − plan total.
  - Suggestions come in four kinds: `remove | pause | swap | reduce`. Each has tap-only Q&A and `facts`: plain-language background with every number a user might ask about, which is what the chat model answers from. Optional `detailNote` and `steps` drive the Detail screen; `reduce` has a required `unit` ("kpl" / "cans", "kertaa" / "times"), `swap` an optional `changedLabel`. A swap's `from` / `to` products can carry an `image` (packshots live in `assets/products/`, cropped to ~320 px); the Review card shows them in a plain "Nyt → Halvempi" comparison panel with no borders, so it doesn't read as two buttons. Suggestions shared between sets (Wolt, HBO, cheese) are shared builders, so their `src/ai/placeholder.ts` texts (keyed by id) work in both.
  - `basic` ("Perustilanne", the mockups): all defaults give 64 € → 122 € (+58 €). Re-check that if you edit amounts.
  - `tight` ("Tiukka kuukausi"): the money runs out before payday, −40,28 € → +58,96 € (+99,24 €), crossing zero on the 3rd card. It includes the HSL swap from single tickets to a season ticket (HSL's 2026 fares: AB single 3,30 €, 30-day continuous order 61,60 €). The user takes ~40 trips a month (132 €), but the forecast to payday has only ~20 (66 €), so the card saves just 4,40 € before payday; the card text, Detail note and Kerro lisää lead with the ~70 €/month saving instead. `HSL_PLAN` / `HSL_TRIP` are shared with `near-zero`. The transfer card never shows here, because the margin is below `TRANSFER_BUFFER`.
  - `near-zero` ("Lähes nollassa"): only 8,00 € left on payday. Cards in order HBO, HSL, Battery, Wolt, cheese; all defaults give 8,00 € → 78,50 € (+70,50 €). Battery here is 13 cans → 4 (`NEAR_ZERO_CANS`; `BATTERY(L, current)` / `BATTERY_PLAN(L, current)` default to 10 for `basic`). The transfer card suggests 25 € (capped by `TRANSFER_BUFFER`, not `TRANSFER_SHARE`), leaving ~53 € (~18 € if half fails). Re-check if you edit amounts.
- `src/ai/`: the "Kerro lisää" explainer and chat. `placeholder.ts` has the hand-written texts in both languages (picked by `ctx.demo.lang`): the explanation card (`explanationFor`, `transferExplanation`) and the chip answers (`qa` in data.ts, `transferAnswers`). Screens only call `explainer` / `transferAdvisor` from `explainer.ts`. A question that matches a chip gets its ready answer; anything typed is POSTed (prompt, history, question) to the server route `src/app/api/chat+api.ts`, which calls Gemini with the server-only `GEMINI_API_KEY` (model `GEMINI_MODEL`, default `gemini-flash-lite-latest`). The key comes from `.env.local` locally and from the EAS `production` environment when deployed (`eas env:create`, sensitive); it must never get an `EXPO_PUBLIC_` prefix, which would bundle it into the client. On native, the relative `/api/chat` goes to the dev server in development and to the `origin` in app.json (the hosted site) otherwise. The route caps sizes and rejects other websites' origins. Without a key typed questions get a "not enabled" reply; on errors a "try again" one. The prompt (`suggestionPrompt` / `transferPrompt`) is plain text built for a cheap model: rules, the scenario (balances, forecast, transactions), the suggestion's `facts`, the explanation on screen, the ready Q&A and how the app works. To make the chat answer something new, add a fact to the suggestion, not to the prompt.
- `src/components/`
  - `OutcomeBars`: the single outcome visualisation. With a negative baseline it has two phases ("täytä vaje ensin"). In the `fill` phase the whole bar is the shortfall (red tint, dashed red outline) and accepted savings fill it in yellow like a progress bar; the legend reads "Vaje X €" / "Katettu Y € / X €". Once the balance is ≥ 0 it switches to the normal 0 €-to-best-outcome scale, where what's left is all yellow (no green, since none of it exists without the savings). Crossing zero animates the old phase to its end (full, or empty when going back), switches scale, then grows on; `shown` lags `phase` during that. The number turns from red to green at zero.
  - `PlanRow`: the cleanup and flash animations.
  - `ui.tsx`: `T`, `Press`, `Btn`, `Cta` (the big green call-to-action), `Header`, `Body`, `Card`, `Pill`, `AnimatedNumber`, and the haptics helpers.
  - `Icon`: SVG icons traced from the mockups.
  - `TabBar`.
- `src/screens/`: `Home`, `Save` (the hub), `Review` (suggestion cards; after the last card it goes straight back to `Save`, with no summary screen), `Shopping` (currently unreachable: every "Katso kauppalista" entry point was removed for now), `Detail`, `Learn` ("Kerro lisää": the shared `LearnView`, used by `Learn` for suggestions and `LearnTransfer` for the transfer), `Account` (S-Tili) and `EtuCard` (S-Etukortti) are placeholders: both render `NotInDemo` from `Other`, a header plus "Tämä sivu ei ole käytettävissä demossa". `Other` also has Minä, with the demo-set picker and the "Nollaa demo" reset.

## Product rules (from the brief)

- **Chat stays grounded.** "Kerro lisää" (`LearnMore`, a plain green text link with a ">" chevron right under the card's reason text → `Learn` screen) shows an educational explanation (why / what it means / one money concept / data source), tap-only follow-up questions, and a free-text field ("Kysy omin sanoin…") answered by the model from the suggestion's facts only.
- **Only claim what a bank can see:** card transactions and S-Etukortti item-level purchases. Never how often a service is used or opened.
- **One simple outcome visualisation**: a single bar that updates immediately. It starts at the no-changes estimate (green), then accepted changes grow on its end (solid yellow) and the suggestion being looked at shows as a dashed segment. The big number is baseline + accepted; the dashed preview is never part of the number. It is a dashed legend entry under the bar: "Mahdollista +X €" on the Säästä tab, "Jos hyväksyt +X €" on the Review cards. On both, the legend entries are stacked one per row (Ilman säästöjä, Säästösi, then the dashed one). The Säästä tab's hero is centered: "Arvioitu saldo" as the block's title (large, dark), "Palkkapäivänä {date}" under it, then the big number.
- **Completed transactions never change.** Only the forecast (`demo.plan`) changes.
- **Users can protect purchases.** "Hylkää" on a suggestion card sets the decision to `kept` and shows a lock tag.
- **A cancelled change is never suggested again.** "Peru tämä säästö" on `Detail` sets the decision to `kept`, not back to `pending`.
- **The forecast is an estimate from past spending.** Say so wherever forecast numbers appear ("arvio", "Arvioidut menot", the "Ennuste aiemmista ostoistasi" note on the Säästä tab).
- **The Säästä tab has no title bar.** Its top is a white hero (outcome bar, CTA) flush with the white status-bar area.
- **Suggestion cards never scroll.** `Review` is a fixed layout that must fit one screen, and the tab bar is hidden on it (see `Shell` in `App.tsx`). Check it at 390×844 and on a small screen after any copy or layout change.
- **The Koti card only invites.** It shows only while suggestions are pending; with none left it disappears.
- **Savings become real money:** after the last suggestion card, the Säästä hero shows the "Siirrä säästöön" card in place of the CTA. It starts closed, as a dropdown styled like "Arvioidut menot" (the label "Suositus: Siirrä säästöön", "Ehdotus vapauttamastasi rahasta", the amount in big green and a chevron in a white circle). Opened, it adds a reason grounded in the user's data, Kerro lisää, then one white panel: "S-Tili → Säästötili X €" and two checks, the buffer left on payday and what's left even if half of the savings fail (`ifHalfFails`); then "Ei nyt" / "Siirrä", and the "Siirrä eri määrä ›" link that turns the amount into a −/+ stepper. The suggested amount is always smaller than what was saved. "Ei nyt" hides it for good. A transfer lowers S-Tili and raises Säästötili on Koti; the outcome bar doesn't change. (The Pankki tab used to list it as a new transaction, but that tab is now a placeholder.)
- **Accepted changes lead somewhere useful:** cancellation steps for subscriptions. (The shopping list and prepared basket are hidden for now.)

## Gotchas

- **Fonts:** Figtree has one font family per weight. Use `font(weight, size, color)` or `<T w={700}>`, never `fontWeight`.
- **`Press`:** its `style` applies to the inner animated view. For layout on the touch target (e.g. `flex: 1` in a row), pass `containerStyle`.
- **Dashed bar segment:** drawn as one fully rounded dashed rect *behind* the solid bars, because iOS can't render dashed borders on partial sides. Bar widths are animated in pixels after `onLayout`; `Animated.add` with plain numbers isn't used.
- **ScrollView ref type:** in RN 0.88, use `import type { ScrollViewInstance } from 'react-native'` for ScrollView refs.
- **Plan total on the Säästä tab:** it subtracts a change only once its row is `cleaned`, so the total ticks down in sync with the animation. While the "Arvioidut menot" dropdown is closed the rows aren't mounted, so `Save` marks pending rows `cleaned` straight away; the animation only plays when the list is open.
- **Android tab bar inset:** Expo Go on Android can report a bottom safe-area inset that's too small, so the edge-to-edge navigation bar covers the tab bar. `TabBar` sets a 48 dp minimum bottom padding on Android. Don't drop it back to the plain inset.
- **Keyboard:** the app is edge-to-edge, so Android doesn't resize the window for the keyboard. `Shell` pads the screen by `useKeyboardHeight()` (`src/components/keyboard.ts`) and hides the tab bar while the keyboard is open, so the "Kerro lisää" chat field sits right above it; `LearnView` hides the question chips meanwhile. Don't add a `KeyboardAvoidingView` on top, or the padding doubles.
- **Web is public:** the web build on EAS Hosting (https://s-mobiili-demo.expo.app, behind the QR code in the video) is how most people try the demo, so it has to work on phone browsers too. `src/app/+html.tsx` is the web template: viewport/safe-area meta, home-screen meta, and, at widths ≥ 600 px, a phone frame that always lays out at 390×844 and is scaled down as a whole (`--phone-scale`, set by an inline script) to fit short laptop screens, so the aspect ratio stays a real phone's. `useWindowDimensions()` still reports the browser window there, not the frame. The Gemini key stays on the server (see `src/ai/`). In SDK 58 `+html.tsx` must render `headNodes` / `bodyNodes` from `useServerDocumentContext()`, or the page never loads the app's script. `useNativeDriver` warnings on web are expected. Haptics only work on a real device.
- **UI checks:** export the web build (`npx expo export --platform web --output-dir <dir>`), serve it, and drive it with Playwright at 390×844. Write the output to a scratch dir, never inside the project. On Windows, stop the static server before re-exporting into the same dir, or the export fails with EBUSY.
